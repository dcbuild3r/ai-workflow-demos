# Personal White-Label Voiceover Script

AI for daily life

This is the personal version: a public-safe walkthrough of a daily AI stack. The goal is simple: make agents useful across real tools, real memory, and real workflows, not just inside a chat window.

Agenda

The path is the mental model first, then the stack: Runner, Obsidian, a public surface, a personal dashboard, Co-typist, and Codex. Then I will show how a request becomes filed learning.

Part 1: Mental model

The system starts with a shape. Context is the base, personal agents act on top of it, and the team version is a scoped, permissioned subset of the same primitive set.

Three concentric layers

At the center is context: notes, memory, projects, finances, health, and references. Around that are personal agents like Runner, Codex, and Co-typist. The outer layer is the team version, where access is narrowed and audited.

Part 2: Runner

Runner is the chief-of-staff layer. It is the agent that talks to the rest of the world, pulls context, drafts work, and turns recurring tasks into reusable skills.

Runner

Runner drafts replies, books meetings, runs research, and keeps persistent memory across sessions. The key detail is approval. It can prepare action cards, but important outbound sends do not happen silently.

Part 3: Obsidian

The durable base is Obsidian. It is not fancy because it does not need to be. Plain markdown, git history, and wikilinks make the knowledge base readable by humans and agents.

Obsidian

The structure matters. Capture goes into raw notes and clippings. The wiki layer holds canonical entities. Work gets project folders. Personal operations like finance and health live in their own zones.

Public surface + personal dashboard

The stack has two built surfaces. A public surface for writing, projects, APIs, and structured data. Then a personal dashboard over the vault, where charts and views can be regenerated or updated by skills.

Contacts

Contacts are not just an address book. They become relationship memory: origins, channels, context, and follow-up signals. In this public version, the private data is redacted, but the workflow shape is still visible.

Media queue

The media queue turns saved videos, books, podcasts, and notes into searchable input. Instead of losing good material in a pile of tabs, it becomes something an agent can summarize, prioritize, and reuse.

Network graph

The network graph makes social context inspectable. It helps rank relationships, find research paths, and understand where attention is concentrated without relying on memory or vibes.

Folded knowledge graph

The folded graph gives a clean folder-level map of the knowledge base. It is the zoomed-out view: useful when you want to understand the shape before opening individual notes.

Full knowledge graph

The full graph is the detailed view. It is dense, but useful when you need to inspect real links, clusters, and unexpected connections inside the personal operating system.

Co-typist

Co-typist sits at the keystroke layer. It gives system-wide ghost text in everyday apps, and because it runs locally on Apple Foundation Models, sensitive typing can stay on device.

Codex

Codex is the coding harness. It works on the public surface, the dashboard, Runner skills, scripts, and infrastructure. The pattern is deterministic orchestration, short-lived agents, worktrees, and file-based state.

How it fits together

The clean flow is: personal context feeds personal agents, and those agents act on the built surface. Obsidian is the memory. Runner is the hands. Codex builds and repairs the system.

A request becomes a graph of work

A useful request is not one chat response. The agent pulls context, uses tools, applies the right voice, returns drafts for approval, then files useful learning back into the knowledge base.

The operating rails

The rails keep the loop reliable. There is a vault contract, memory with reasons, deferred connectors, reusable skills, style profiles, and verification guardrails for anything visual, destructive, or production-facing.

Demo plan: Part 1 of the sync

For a demo, I would show inbox triage and calendar booking, the dashboard over the vault, a public site update written by an agent, and one Codex run on the dashboard frontend.

Now: the team version.

That is the personal stack. The team version keeps the same primitives, but scopes them for shared work: permissions, audit trails, channel context, and company tools.
